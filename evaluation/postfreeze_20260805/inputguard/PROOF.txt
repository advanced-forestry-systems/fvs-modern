PROOF 4 -- TREE_ID 32-bit overflow claim
==============================================================================
File: /users/PUOM0008/crsfaaron/fvs-modern/src-converted/dbsqlite/dbstreesin.f90
INTEGER ITREE,IPLOT,HISTORY,CRWNR,DMG1,DMG2,DMG3,SVR1,SVR2
   CASE('TREE_ID')
     ITREE = fsql3_colint(IinDBref,ColNumber,0)
     MATCHED=.TRUE.
30:integer  fsql3_step,fsql3_finalize,fsql3_colisnull, &
31-            fsql3_colname,fsql3_colcnt,fsql3_colint,fsql3_coltext
32-real*4   fsql3_colreal

ITREE is a DEFAULT Fortran INTEGER (line 20), bound to the TREE_ID column
by fsql3_colint (line 97).  Default INTEGER on this build is 4-byte
signed, max 2147483647.
A real FIA control number from the plot list, 107545100010661, is 15 digits and
evaluates to 107545100010661, which is 5.01e+04 times the signed 32-bit maximum.
OVERFLOW CONFIRMED.  The full CN can never be used as TREE_ID; the guard
allocates tree_id = stand_index * 10000 + tree_seq, whose maximum on the
3,321-stand list is 33219999, comfortably inside 2147483647.
